# Ashta Chamma 3D

A web-based 3D multiplayer modernization of the traditional Indian board game
**Ashta Chamma** (aka *Daayam*, *Tabla*) — built on **React Three Fiber +
FastAPI + PostgreSQL + Redis** and deployed to **AWS**.

> **Background:** [Ashta Chamma on Wikipedia](https://wiki2.org/en/Ashta_Chamma_(board_game))

This repository is a monorepo containing the browser client, the server-authoritative
game backend, AWS CDK infrastructure stacks, and project documentation. The legacy
pygame implementation (`game.py`, `player.py`, `path.py`, `helper.py`) is preserved
at the repo root as a rule-fidelity reference until the new engine reaches feature
parity.

## Local Development Setup

### Prerequisites

| Tool | Version | Purpose |
|---|---|---|
| Node.js | 20+ | React client |
| Python | 3.12+ | FastAPI backend |
| Poetry | 1.8+ | Python dependency management |
| Docker | 24+ | Local PostgreSQL + Redis via Docker Compose |
| AWS CDK | 2.x | Infrastructure deployment (optional for local dev) |

### Client (React + Vite + TypeScript)

```bash
cd client
npm install
npm run dev        # dev server at http://localhost:5173
npm run build      # production build → dist/
npm run lint       # ESLint + Prettier checks
```

TypeScript is configured with `"strict": true`. Linting uses **ESLint 9
(flat config)** + `typescript-eslint`.

### Server (FastAPI + Poetry)

```bash
cd server
poetry install     # or: uv sync
poetry run uvicorn app.main:app --reload --port 8000
```

API documentation is auto-generated by FastAPI and available at:

- **Swagger UI:** <http://localhost:8000/docs>
- **ReDoc:** <http://localhost:8000/redoc>
- **OpenAPI JSON:** <http://localhost:8000/openapi.json>

Run tests and linting:

```bash
cd server
poetry run pytest          # unit tests
poetry run ruff check .    # linting
poetry run mypy .          # type checking
```

### Local Services (Docker Compose)

```bash
# Start PostgreSQL and Redis locally
docker compose up -d postgres redis

# Stop services
docker compose down
```

Environment variables for local development (copy `.env.example` to `.env`):

| Variable | Description |
|---|---|
| `DATABASE_URL` | PostgreSQL connection string |
| `REDIS_URL` | Redis connection string |
| `CLERK_SECRET_KEY` | Clerk secret key for JWT validation |
| `CLERK_PUBLISHABLE_KEY` | Clerk publishable key for the SPA |

## Architecture

The system is a cloud-native, multi-tier architecture:

```
React SPA → CloudFront/S3 (static)
React SPA → WAF → ALB → ECS Fargate (FastAPI) → RDS PostgreSQL
                                               → ElastiCache Redis (pub/sub)
React SPA → Clerk (authentication)
```

Key architectural decisions:

- **Server-authoritative game logic** — clients send intents; server validates
  and broadcasts state. No game logic runs on the client. (→ [ADR-003](docs/adr/003-game-state-architecture.md))
- **WebSocket + Redis pub/sub** for real-time game events across multiple ECS
  tasks. (→ [ADR-004](docs/adr/004-realtime-communication.md))
- **Clerk** for authentication — RS256 JWTs validated via JWKS. (→ [ADR-002](docs/adr/002-authentication-provider.md))
- **AWS ECS Fargate** with stateless tasks, auto-scaling on CPU. (→ [ADR-001](docs/adr/001-modernization-strategy.md))

See **[docs/architecture.md](docs/architecture.md)** for full diagrams and details.

## API Reference

The FastAPI backend auto-generates interactive API documentation:

- **Swagger UI** (development): `http://localhost:8000/docs`
- **ReDoc** (development): `http://localhost:8000/redoc`
- **Production:** `https://api.ashta-chamma.example.com/docs`

Key endpoints:

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/health` | Health check (no auth) |
| `POST` | `/api/rooms` | Create game room |
| `GET` | `/api/rooms/{code}` | Get room details |
| `POST` | `/api/rooms/{code}/join` | Join a room |
| `GET` | `/api/scores/leaderboard` | Leaderboard |
| `GET` | `/api/users/me` | Current user profile |
| `WSS` | `/ws/rooms/{room_id}` | Real-time game connection |

## Infrastructure (AWS CDK)

Infrastructure is defined as TypeScript CDK stacks in `infra/`:

```bash
cd infra
npm install
npx cdk diff        # preview changes
npx cdk deploy --all   # deploy all stacks
```

CDK stacks:
- **NetworkStack** — VPC, subnets, NAT gateway, security groups
- **DatabaseStack** — RDS PostgreSQL 16, RDS Proxy, ElastiCache Redis
- **ComputeStack** — ECS cluster, Fargate service, ALB
- **CdnStack** — S3 bucket, CloudFront distribution
- **MonitoringStack** — CloudWatch dashboards, alarms, X-Ray
